## 1. Де ми зараз (v2.9.2)

| Можливість | Стан |
|---|---|
| Перегляд (VFS) | `.tar`, `.tar.gz/.tgz`, `.zip`/ZIP64 і zip-подібні (`docx/jar/apk/whl/epub…`) без лімітів розміру/кількості; ustar-prefix, GNU `L/K`, PAX, base-256, UTF-8/CP437, SFX-префікс, перевірка перекриття записів |
| Декодери | потоковий DEFLATE/Deflate64 (`inflate_stream.c`), gzip multi-member з CRC/ISIZE (`gzip_dec.c`) |
| Розпакування / тест | `F5` в архіві, `Alt+F9`, `Alt+Shift+F9`; `openat(O_NOFOLLOW)`, Zip-Slip/symlink/hardlink-захист, `.duop-part` + CRC + `rename`, smart-unpack, анти-бомба (>1 ГіБ і >1000:1), конфлікти, прогрес/скасування |
| Тести | диференційні, fuzz (`test_arc_fuzz.py`), faultlab, PTY, aarch64/qemu |
| **Немає** | `.xz/.bz2/.zst` (і `.tar.*` від них), одиночний `.gz`, zip-методи 12/14/93/95, пакування, зміна архіву, шифровані записи, `.7z/.deb/.rpm/.cpio/.iso`, CLI |

**Відомий техборг:** (1) `.tar.gz` відкривається **синхронно** з повною декомпресією у temp до 512 МіБ ([arc_source.c](../src/fs/arc_source.c)) — для повільніших кодеків це заморожує UI (`duop-liveness-timeouts`); (2) `ArcEntry` 288 Б і `archive_parse.c`/`arc_ungzip` живуть лише заради `pkg_archive.c`; (3) вибір формату за розширенням, а не за магією; (4) `F3` великого запису синхронний; (5) CRC-32 — табличний, без SIMD; (6) немає SHA-1/AES/XXH64 у `src/core`.

## 2. Принципи та переупорядкування

Старий порядок «пакування → кодеки» змінюємо на **«читання повністю → пакування → зміна → шифрування»**, бо:

1. Найчастіший реальний збій користувача зараз — `Enter` на `.tar.xz` / `.tar.zst` / `.tar.bz2` / `.deb` / `.pkg.tar.zst` (джерела ПЗ, пакети дистрибутивів, ядро). Це **повідомлення «не підтримується»** — найгірша точка першого враження для файлового менеджера.
2. Кодеки-декодери — вхід для `.deb/.rpm/.7z/squashfs`; пакувальник їм не потрібен.
3. Декодер без fuzz-стійкості небезпечніший за відсутність декодера: кожен кодек іде **окремим комітом** зі своїм fuzz і диференційним тестом.
4. Пакування (`deflate` + `tar/zip_write`) — окрема, добре обмежена фаза; кодек zstd-**запису** додається лише після неї.

Незмінні інваріанти (`AGENTS.md`, `duop-*`): тести першими; кожен `mem_alloc/os_*` перевіряється; без рекурсії по дереву архіву; усі ліміти мають локалізоване повідомлення; i18n у `types.inc`/`lang_strings.inc` + `*.lang`; модулі ≤500 рядків, функція ≤80, ≤16 експортів; SemVer + Conventional Commit після `verify_build.sh`.

## 3. Фази

### Фаза 3 — Фундамент і швидкі перемоги (`v2.9.3 → v2.9.x`, розмір S–M)
Передумови для всіх кодеків; без них xz/zstd зроблять UI гіршим, а не кращим.

1. **Асинхронне відкриття стиснутого tar:** декомпресія в `TaskWorker` (`TASK_OP_ARCOPEN`) у безіменний temp-fd з прогресом і `Esc`; `ENOSPC`/ліміт → зрозуміла помилка; вибір temp-каталогу (`$TMPDIR` → тека архіву → `O_TMPFILE`), pre-flight `fstatfs`. Прибирає синхронні 512 МіБ.
2. **Диспетчер кодеків за магією:** `ArcCodec { sniff(magic), decode(), name }` у `arc_codec.c` + `include/duop_codec.h`; тип визначається за першими байтами (`1F 8B`, `FD 37 7A 58 5A 00`, `28 B5 2F FD`, `BZh`, `PK`, `ustar`@257, `!<arch>`, `07 07 07`/`070701`, `7z BC AF 27 1C`), розширення — лише підказка (перейменовані файли відкриваються).
3. **Одиночний `.gz`** як віртуальний архів з одним записом (`gzip_dec` уже є): `Enter`/`F3`/`Alt+F9`/тест. Той самий шлях потім бере `.xz/.bz2/.zst/.lzma`.
4. **CRC-32 slice-by-8** (C) → пізніше PCLMUL/PMULL у PAL (`pal_simd.s`); baseline-бенчмарк `inflate`/`gzip`/CRC (MB/s) зафіксувати **до** змін, щоб ловити регресії.
5. **Прев'ю архіву у `F9`-панелі:** формат, кількість файлів/тек, розпакований/стиснений розмір, коефіцієнт, перші N записів, коментар (цілком у межах mmap-індексу, без декомпресії вмісту).
6. **Інфо-рядок/Properties:** «ZIP · 1 234 файли · 56→12 МіБ · метод · зашифровано/ні».
7. **Конфіг-ключі лімітів** (`arc_open_max_mb`, `arc_mem_limit_mb`, `arc_bomb_ratio`) у `duoprc`; документація, **синхронізація ROADMAP §4.1 / USER_GUIDE** (`duop-docs-sync`).

**DoD:** відкриття 400 МіБ `.tar.gz` не блокує UI >100 мс; `Esc` не лишає temp-файлів (SIGKILL — теж); `.gz` і перейменований архів відкриваються.

### Фаза 4 — Декодери для читання (`v2.10.x`, розмір XL; три окремі коміти)
Контракт `CodecSink`/`CodecResult` ([duop_codec.h](../include/duop_codec.h)) уже є: вхід цілий (mmap), вихід потоковий, скасування кожні 64 КіБ.

| Порядок | Кодек | Модулі (оцінка) | Особливості / ліміти | Чому саме тут |
|---|---|---|---|---|
| 4.1 | **zstd** | `zstd_dec.c`, `zstd_fse.c`, `zstd_huf.c` (~1100 рядків) + XXH64 у `hash.c` | кадри, skippable frames, FSE/Huffman, sequences, контрольна сума XXH64; `windowLog ≤ 27` за замовчуванням, інакше `-EOPNOTSUPP` з текстом «потрібен `--long`/пам'ять» | `.pkg.tar.zst`, `.deb` (Ubuntu ≥21.10), RPM, ядро; найшвидший у декомпресії |
| 4.2 | **xz + LZMA2** (+ `.lzma`) | `lzma_dec.c`, `xz_dec.c`, `xz_filters.c` (~1000 рядків) | контейнер xz (index/footer, multi-stream, padding), check CRC32/CRC64/SHA-256, BCJ x86/ARM/ARM64/RISC-V/PPC/SPARC + Delta; словник проти `arc_mem_limit` | `.tar.xz` — тарболи ПЗ, найпоширеніший формат дистрибутивів |
| 4.3 | **bzip2** | `bzip2_dec.c` (~450 рядків) | BWT-обернення, MTF/RLE2, Huffman, CRC блоку й потоку, multi-stream; пам'ять 900 КБ × блок | legacy, але масово; найпростіший |

Підключення: `.tar.xz/.txz/.tar.zst/.tzst/.tar.bz2/.tbz2/.tlz`, одиночні `.xz/.zst/.bz2/.lzma`, zip-методи **12 (bzip2), 14 (LZMA), 93 (zstd), 95 (xz)**, `ARC_TGZ` → узагальнений `ARC_TAR_COMPRESSED{codec}`.

**Тести на кодек:** диференційно проти Python `lzma`/`bz2` і CLI `xz`/`zstd`/`bzip2` (у Python 3.12 немає `compression.zstd`, тому для zstd еталон — CLI); офіційні тест-вектори (xz `tests/files`, zstd `tests/golden-*`, bzip2 `sample*`); вхід, порізаний на всіх межах; fuzz «будь-який вхід → `-EINVAL`/обмежена пам'ять, ніколи вихід за буфер»; SEU-перевірка статичних таблиць; `MEMCHECK=1`; qemu-aarch64. **Безпека:** обмеження словника/вікна/кількості блоків, `-EFBIG` за `max_out`, жодного нескінченного циклу на корупції (лічильник ітерацій на кожен цикл декодування).

**DoD фази:** `diff -r` результату `Alt+F9` з `tar xf` на корпусі з усіх кодеків; продуктивність ≥ 50 % від еталонних `xz/zstd/bzip2` (мета; нижче — документований компроміс); приріст ELF ≲ 40 КБ (оцінка, не гейт).

### Фаза 5 — Контейнерні формати (`v2.11.x`, розмір M–L)
Дешеві поверх Фази 4, дуже цінні для DevOps/SRE:

1. **`.deb` / `.ar` / `.a`** (`arc_ar.c`): `data.tar.{gz,xz,zst}` відкривається як вкладена тека, `control.tar.*` — окремо.
2. **`.rpm`** (заголовок + payload `cpio.{gz,xz,zst}`) та **`.cpio`/initramfs** (newc/odc/crc; конкатеновані архіви, `TRAILER!!!`) — `arc_cpio.c`.
3. **OCI/Docker-шар:** tar із `.wh.`-whiteout і `.wh..wh..opq` показуються як «видалено в шарі»; `manifest.json` → перелік шарів (docker save).
4. **`.7z` (лише читання)** (`arc_7z.c`): стартовий/кінцевий заголовок, закодований заголовок (LZMA), solid-блоки, фільтри BCJ/Delta/BCJ2, CRC; шифрований — «не підтримується» (до Фази 8). Дає `.7z` без нових кодеків.
5. **`.iso` (ISO 9660 + Joliet + Rock Ridge)** (`arc_iso.c`): лише читання, без декодера — образи ОС/cloud-init.
6. **`.squashfs`/AppImage** — **рішення-шлюз** (потрібні zlib/xz/zstd/lz4; lz4 — новий декодер): робимо, лише якщо буде попит.
7. Архів в архіві (глибина ≤ 2): вкладений архів → безіменний temp → той самий конвеєр; сумарний ліміт розпакованого.

**DoD:** кожен формат має корпус із системних утиліт (`ar`, `cpio`, `7z a`, `genisoimage`/`xorriso`), fuzz, нуль `.duop-part`-залишків.

### Фаза 6 — Пакування (`v2.12.x`, розмір XL; колишня Фаза 3)
1. **`deflate.c` + `deflate_huff.c`**: рівні `store`/`fast`/`normal` (hash-chain + lazy), dynamic Huffman з довжинами ≤15, пам'ять ≤1 МіБ; **детермінований** вивід (однаковий вхід → однаковий байт-в-байт результат).
2. **`tar_write.c`** (ustar + PAX для довгих імен/великих значень/UTF-8), **gzip-обгортка**, **`zip_write.c`** (ZIP64 автоматично, UTF-8 flag, `0x5455`, unix-атрибути, data descriptor для потокового запису).
3. **`archive_pack.c`** (`TASK_OP_PACK`): сортований обхід без рекурсії, `O_NOFOLLOW`, виключення самого вихідного архіву за `dev/ino`, політика symlink (зберегти/слідувати), дедуплікація hardlink у tar, файл змінився під час читання → позначка + помилка, виключення (`.git`, шаблони), `SOURCE_DATE_EPOCH` і `--owner=0`-режим (**reproducible builds**).
4. **`pack_dialog.c`** + `Alt+F5`: формат (`tar`, `tar.gz`, `zip`, далі `tar.zst`), рівень, ім'я, «перевірити після пакування» (реюз `arc_test`), «пакувати окремо кожен елемент».
5. Вивід атомарний: `.duop-part` → `fsync` → `RENAME_NOREPLACE`; ENOSPC → видалення частини.
6. **Після стабілізації:** запис **zstd** (рівні 1–3: greedy/lazy + FSE/Huffman encoder; `tar.zst` — сучасний дефолт) і за потреби нескладний LZMA-encoder; **bzip2-запис — свідомо ні**.

**Тести:** round-trip через Python `tarfile/zipfile`, `unzip -t`, `tar -tzf`, `7z t`, `zstd -t`; декомпресія нашим `inflate_stream` ≡ вхід; ZIP64 >4 ГіБ на sparse-файлі; faultlab (ENOSPC/EIO/SIGKILL посеред пакування); відтворюваність.

### Фаза 7 — Зміна існуючих архівів (`v2.13.x`, розмір L)
`F5` з фс-панелі в архівну = **додати**, `F8` = **видалити запис**, `F6` = **перейменувати**/перенести всередині архіву.
- **zip:** швидкий шлях «дописати дані + новий central directory»; видалення/перейменування — переписування у temp + `rename` (з `copy_file_range`/reflink, де є).
- **tar / tar.\*:** повне переписування у temp (для стиснених — перекомпресія з тим самим кодеком/рівнем, якщо кодек запису є; інакше режим залишається read-only з поясненням).
- **Crash-consistency (`duop-crash-consistency`):** оригінал ніколи не змінюється до `rename`; тест SIGKILL на кожній межі syscall; блокування за `dev/ino/mtime` (архів змінився зовні → відмова).
- Коментар архіву (zip) — перегляд/редагування.

### Фаза 8 — Шифрування (`v2.14.x`, розмір L; окреме рішення-шлюз)
Потребує нових примітивів у `src/core` (SHA-1, HMAC, PBKDF2, AES-128/256 — `AES-NI`/`ARMv8 AES` через PAL, constant-time C як fallback).
1. **Читання:** ZipCrypto (історично слабкий — лише для читання старих архівів), **WinZip AES-256** (AE-1/AE-2), 7z AES-256 (SHA-256 KDF, 2^19 раундів — потрібен прогрес/скасування).
2. **Запис:** лише **AES-256** (ZipCrypto не пропонуємо). Інтеграція в Фазу 6 (прапорець у `pack_dialog`).
3. **UX/безпека:** діалог пароля з маскуванням; пароль ніколи не в `argv`, історії, логах, ops.log чи core-dump (`PR_SET_DUMPABLE=0` на час операції, `mlock`, обнулення `volatile`-записом); порівняння MAC у constant time; неправильний пароль → зрозуміла помилка, а не «пошкоджений архів».

### Фаза 9 — Масштаб, швидкодія, CLI (`v2.15.x`, розмір L)
- **Довільний доступ без повної декомпресії:** xz-індекс блоків, zstd seekable-формат, gzip-checkpoints (zran, вікно 32 КіБ) + **персистентний кеш індексу** у `~/.cache/duop` за ключем `dev/ino/size/mtime` (повторне відкриття `.tar.gz` на 5 ГіБ — миттєве).
- **Паралелізм** через PAL-потоки: незалежні блоки bzip2/xz/zstd-кадри при розпакуванні, pigz-подібне пакування; детермінований вивід зберігається.
- **SIMD:** CRC-32 PCLMUL/PMULL, швидкий шлях `inflate`, XXH64; бенчмарк-звіт vs `gzip/unzip/xz/zstd/bzip2/7z/bsdtar` ([BENCHMARK-стиль](BENCHMARK_20M_2026-11-17.md)).
- **Потоковий `F3`** для великих записів через worker із прогресом.
- **Міграція `pkg_archive.c`/`dir_search.c` на новий API**, видалення `archive_parse.c` та compat-`ArcEntry`.
- **Headless CLI:** `duop x|a|t|l <archive>` (розпакувати/пакувати/тест/список) без TUI — сценарії CI, `FROM scratch` rescue-образ ([ROADMAP §4.2](../ROADMAP.md)), де немає `tar/unzip`; той самий движок і той самий код безпеки.
- **Інтеграція:** Drop Stack → «Пакувати»; `Alt+=` порівняння двох архівів/архіву й теки; `Ctrl+F` пошук за вмістом усередині архівів; `Alt+K`-розширення можуть реєструвати формати через VFS-контракт.

## 4. Наскрізні вимоги

| Область | Вимога |
|---|---|
| Тестування | Для кожного формату/кодека: fixture-корпус (`tests/archive_fixtures.py`), диференційний тест проти еталонних утиліт, детермінований fuzz (bit-flip/truncate/overlap/bomb), faultlab (OOM, EIO, ENOSPC, SIGKILL), `MEMCHECK=1`, qemu-aarch64, перевірка `audit_live_regs.py` |
| Безпека | Недовірений вхід: усі зсуви без переповнення; ліміти (записи, глибина, словник, вікно, відношення розпакування, вкладеність); жодного `symlink`/`..`/пристроїв при розпакуванні; case-/Unicode-колізії імен повідомляються; ключі й паролі обнуляються |
| Відмовостійкість | Атомарний вивід, `fsync`, `RENAME_NOREPLACE`, SEU-перевірка статичних таблиць і контрольних структур, `verify after pack`, опційна SHA-256-перевірка після розпакування |
| Liveness | Жодних блокувальних викликів у UI-циклі: усе важке — у `TaskWorker`; скасування кожні 64 КіБ; таймаути на зовнішні процеси |
| Портативність | Тільки `os_*`/`load_le*`, без `libc`/VLA/`__int128`/float; `arc_path` не робить припущень про POSIX-імена (готовність до [Windows-порту](WINDOWS_PORT_PLAN.md): `\`, зарезервовані імена, нечутливість до регістру) |
| i18n/UX | Кожен рядок — слот `LangStrings` + `i18n_en.lang` + `lang/uk.lang` + решта пакетів; помилки — з причиною та підказкою, а не «не вдалося» |
| Реліз | `VERSION` на кожен крок, Conventional Commit, `verify_build.sh`, оновлення `ROADMAP`/`USER_GUIDE`/`HOTKEYS` (`duop-docs-sync`) |

## 5. Метрики якості (фіксуються в кожній фазі)

- Пропускна здатність декодерів/кодерів (MB/s) і відношення до еталонних утиліт; регресія >10 % блокує реліз.
- Пік RSS: архів 2 ГіБ ≲ 32 МіБ (без урахування temp-файлів), словник кодека враховується окремо.
- Час першого відкриття/повторного (кеш індексу), листинг теки з 100k записів ≪ 100 мс.
- Приріст ELF (звітується, не гейт); кількість знайдених fuzz-падінь = 0 на 10⁶ ітерацій/кодек.

## 6. Ризики та рішення-шлюзи

| Ризик | Пом'якшення |
|---|---|
| Обсяг zstd/xz | кожен у власній гілці/коміті, фаза 6 не залежить від фази 4; можна випускати зі «зупинкою» після будь-якого кодека |
| Безпека декодерів | fuzz і ліміти — частина DoD, не «потім»; жоден кодек не мержиться без диференційного тесту |
| Бюджет модулів (≤500 рядків, ≤16 експортів) | заздалегідь ділити: `*_fse/_huf/_seq`, `lzma_rc/_dec`, `tar_write/_pax` |
| Розмір temp-файлів при `.tar.xz` | pre-flight `fstatfs`, `O_TMPFILE` на цільовій ФС, кеш індексу замість повторної декомпресії |
| Складність редагування архівів | виключно через temp + `rename`; без in-place мутацій до Фази 9 |
| **Шлюз:** `.rar` | формат пропрієтарний (декомпресія RAR3/5 — окремий великий декодер, ліцензійні обмеження на *створення*); за замовчуванням **поза межами**; якщо буде попит — лише читання RAR5 за окремим рішенням або делегування зовнішньому `unrar/7z` через VFS-контракт (з таймаутами та недовірений вивід) |
| **Шлюз:** `squashfs`, `lz4`, `brotli`, `.Z`, `lzip` | не робимо без підтвердженого попиту (§ Фаза 5.6) |
| **Шлюз:** xz/LZMA-**запис** | лише після Фази 6 і за попитом; bzip2-запис не робимо |
